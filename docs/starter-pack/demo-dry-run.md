## Map a saved event truthfully

Map detection to `observed_at`, the saved platform value to `saved_important`, and the saved summary to `ai_summary`. Preserve the source URL and evidence-file reference. Leave unknown publication and capture dates null. A platform process ID is not an email message ID. Use the local fixture ID for an offline example; use the actual trigger message ID only when testing the email route.

Keep `owner`, `backup_owner`, `destination` and `action` visibly proposed until chosen and executed. Save the real run ID, queue-item URL and result only after verifying them. Fill the workflow section of `saved-event-manifest.json` at that point.

## Before stage

- Confirm source access, the signed-in tenant, approved sandbox recipients, connections and queue permissions. Check the current monitor preview.
- Reconcile one relevant event, one repeat and one unreadable item with the queue. Confirm reviewer and backup access. Test notification failure after item creation.
- Download the pack and verify the QR on a phone. Display only the public-source examples.
- Record actual elapsed time. Exit the build at session minute 21 even if incomplete.

## Fallback

After sixty seconds of unexpected loading or authentication, show the local comparison and a proposed review item. Say: “This is the saved source change. These are the fields the workflow should create.” The pack includes real source evidence, while the route remains a configuration recipe until a run is verified. Describe a recorded workflow replay only when the actual input, output, run and destination are available.
